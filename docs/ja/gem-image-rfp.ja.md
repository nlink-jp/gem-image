# RFP: gem-image

> Generated: 2026-04-12
> Status: Draft

## 1. 課題定義

Vertex AI の Gemini 2.5 Flash（Nano banana）はネイティブ画像生成・編集機能を持つが、
Web 版 Gemini ではバッチ的な利用が困難である。
gem-image は、この画像生成機能を CLI から利用可能にし、
シェルスクリプトやパイプラインに組み込めるようにするツールである。

- **対象ユーザー:** 個人利用（nlink-jp 開発者）
- **補完関係:** gem-cli（テキスト生成・画像説明）と相互補完。画像説明は gem-cli のスコープ

## 2. 機能仕様

### コマンド体系

```
gem-image -p "プロンプト" [-i input.png ...] -o output.png [--format png|jpeg]
```

サブコマンドなし。画像生成と画像編集は入力画像（`-i`）の有無で自動判別。

### フラグ

| フラグ | 必須 | 説明 |
|--------|------|------|
| `-p` | ※ | プロンプト。未指定時は stdin から読み取り。`-p` 優先 |
| `-i` | No | 入力画像パス。複数指定可（リピートフラグ） |
| `-o` | Yes | 出力ファイルパス |
| `--format` | No | 出力形式 `png`\|`jpeg`（デフォルト: `png`）。`-o` の拡張子があればそちらを優先 |

※ `-p` 未指定かつ stdin がパイプでない場合はエラー

### 入出力

- **入力:** プロンプト（`-p` またはstdin）、画像ファイル（`-i`）
- **出力:** 画像ファイル（`-o`、必須）
- **ステータス出力:** stderr にトークン消費量を表示（コスト計算用）

### 設定

gem-cli 準拠の方式：

- 環境変数 > 設定ファイル の優先順で評価
- Vertex AI プロジェクトID、リージョン等

### 外部依存

- Vertex AI API（`aiplatform.googleapis.com`）
- Gemini 2.5 Flash（画像生成モデル）
- nlk ライブラリ（guard パッケージ — プロンプトインジェクション対策）

## 3. 設計判断

### 言語・フレームワーク

- **Go** — gem-cli と統一。ビルド・配布の一貫性を維持

### 設計方針

- **UNIX 哲学** — 一つのことをうまくやる。独立ツールとして実装
- **gem-cli との関係** — 独立ツール。設定方式・認証方式は gem-cli を踏襲
- **1リクエスト1処理** — バッチ処理はシェル側で制御。ツール自体はシンプルに保つ

### セキュリティ設計（Security First）

ユーザー入力を受け付けて外部APIに送信するツールのため、セキュリティを最優先で設計する。

| リスク | 対策 |
|--------|------|
| プロンプトインジェクション | nlk/guard パッケージによるノンスタグ XML ラッピング。毎リクエスト新規 Tag 生成 |
| `-i` パストラバーサル | 入力パスの正規化・シンボリックリンク解決・存在確認 |
| `-o` パストラバーサル | 出力パスの正規化・検証 |
| 悪意ある画像ファイル | マジックバイトによるファイル形式検証、ファイルサイズ上限 |
| プロンプト長の悪用 | 入力長の上限設定 |
| 設定ファイル改ざん | ファイルパーミッション検証 |
| 認証情報の漏洩 | ADC 利用。トークン・プロジェクト ID をログ出力しない |
| 出力ファイルのパーミッション | 0644 で生成 |
| セーフティフィルタブロック | 適切なエラーメッセージとエラーコードで通知 |

#### nlk/guard の適用方法

```go
tag := guard.NewTag()
wrapped, err := tag.Wrap(userPrompt)
systemPrompt := tag.Expand("Image generation request is in {{DATA_TAG}} tags. ...")
```

- ユーザープロンプト（`-p` / stdin）を `Wrap()` でノンスタグ XML ラッピング
- システムプロンプトで `Expand()` によりタグ境界を明示
- Tag はリクエストごとに新規生成（再利用禁止）

### スコープ外

- **画像説明生成** — gem-cli で対応済み
- **動画生成** — 別モデルの責務（将来 gem-video として分離の可能性）
- **画像処理ライブラリ的機能** — ピクセル単位のリサイズ・フィルタ等は実装しない
- **stdout へのバイナリ出力** — ターミナル破壊リスクのため対応しない

## 5. 必要な API スコープ / パーミッション

gem-cli と同一：

- **認証:** Google Cloud ADC（Application Default Credentials）
- **IAM ロール:** `roles/aiplatform.user`
- **API:** `aiplatform.googleapis.com` 有効化
- **追加スコープ:** なし（モデルガーデンのモデル利用のため差分なし）

## 6. シリーズ配置

- **Series:** util-series
- **Reason:** gem-cli と同系統のパイプフレンドリーなデータ処理 CLI。UNIX 哲学に基づき独立ツールとして util-series に配置

## 7. 外部プラットフォーム制約

| 制約 | 影響 | 対策 |
|------|------|------|
| Vertex AI クォータ制限（RPM/TPM） | バッチ実行時にレート制限に抵触する可能性 | エラーメッセージで明示。スリープはシェル側で制御 |
| モデル出力解像度制限 | 生成画像のサイズがモデル依存 | ドキュメントに制限値を記載 |
| セーフティフィルタ | プロンプトによってはブロックされる | 適切なエラーコードとメッセージで通知 |
| トークン消費 | コスト管理が必要 | stderr にトークン使用量を表示 |

## 議論ログ

### ツール名・課題定義
- Gemini 2.5 Flash のネイティブ画像生成を CLI から利用したいニーズを確認
- Web 版 Gemini ではバッチ利用が困難なため CLI 化を決定
- 画像説明生成は gem-cli で対応済みのためスコープ外と決定

### コマンド体系
- サブコマンド不要と判断（入力の種類が変わらないため）
- `-o` 必須と決定（stdout への画像バイナリ出力はターミナル破壊リスクがあるため除外）
- 複数入力画像は `-i` リピートフラグ方式を採用
- プロンプトは `-p` フラグ + stdin フォールバック（`-p` 優先）
- 出力形式は `--format` フラグ + `-o` 拡張子自動判定

### 設計方針
- Go 言語、gem-cli と統一
- 独立ツール、UNIX 哲学（「一つのことをうまくやろう」）
- 1リクエスト1処理。バッチはシェル側で制御
- プロンプトベースで可能な編集はスコープ内、画像処理ライブラリ的機能はスコープ外

### セキュリティ
- ユーザー入力を外部 API に送信するため Security First で設計
- nlk/guard パッケージのノンスタグ XML ラッピングをプロンプトインジェクション対策として採用
- パストラバーサル、マジックバイト検証、パーミッション管理等を設計に組み込み

### 開発計画
- Phase 1 で設計ドキュメントを先行作成（詳細設計・開発計画・アーキテクチャ ADR）
- Phase 2 は一括実装（全機能揃わないと E2E テストできないため）
- Phase 3 でドキュメント整備・リリース

### トークン消費量表示
- stderr にトークン使用量を出力する方針を追加（コスト計算用途）
